🔗HTTP E SEU FUNCIONAMENTO🔗


O que é HTTP?

  • O HTTP (HyperText Transfer Protocol) é o protocolo utilizado haver uma comunicação entre clientes (como os navegadores) e servidores na web. Isso define como as informações são solicitadas, enviadas e recebidas.
    Um jeito fácil de entender é, sempre que você acessa um site, envia um formulário até mesmo quando clica em um link, o navegador envia uma requisição HTTP e o servidor responde com uma resposta HTTP.
    O HTTP é sem estado (stateless), ou seja, cada requisição é independente. Para manter informações entre requisições, usamos cookies ou sessões.

Como o HTTP é usado na Web


O HTTP funciona através de requisições e respostas. O processo básico é o seguinte:
  1. O cliente (navegador) envia uma requisição HTTP ao servidor pedindo um recurso (como uma página ou imagem).
  2. O servidor recebe essa requisição, processa e envia uma resposta HTTP, que pode ser o conteúdo solicitado ou uma mensagem de erro.
  3. O cliente recebe a resposta e exibe o conteúdo (ou trata o erro).

Exemplo de Resquet e Response:

1 - Dados Requisição
  • URL de Solicitação: https://www.pudim.com.br/
    → endereço completo requisitado.

  • Método de Solicitação: GET
    → método HTTP que indica que está solicitando o recurso, sem enviar dados no corpo.

  • Código de Status: 304 Not Modified
    → status HTTP indicando que o recurso não foi modificado desde a última requisição, então o navegador pode usar a versão em cache.

  • Endereço Remoto: 85.31.231.84:443
    → endereço IP e porta do servidor que respondeu.

  • Política de Referenciador: strict-origin-when-cross-origin
    → controla quais informações de origem são enviadas no cabeçalho Referer para proteger a privacidade em requisições cross-origin.
2 - Dados Reposta
  • Date: >Wed, 05 Nov 2025 01:24:03 GMT
    → data e hora em que o servidor enviou a resposta.

  • Etag: "65e08720-353"
    → identificador único do recurso que ajuda na validação de cache.

  • Last-Modified: Thu, 29 Feb 2024 13:31:12 GMT
    → última data em que o recurso foi modificado no servidor.

  • Referrer-Policy: same-origin
    → controla quais informações de origem são enviadas na referência da requisição.

  • Server: nginx
    → software de servidor web que respondeu.

  • Response: html
    → documento exibido como parte da resposta responsavel
